# FateGrid｜低負荷工作協議與交接 v0.1
更新：2026-09-23。

## 1. 人的工作負荷是硬限制
使用者已反映每日與 AI 工作超過 12 小時。AI 必須協助減少監督成本；不把長時間工作視為目標或成就。
- 一次只推進一條主工作線。現階段主線是陳老師網站／ERP；FateGrid 僅做知識留存，不插入 Codex 排程。
- 研究性討論建議以 25–50 分鐘為一段；每段有清楚產物和停止點。實際休息節奏由使用者決定。
- 不因為 token 尚有餘額而開新題。跨系統要求放 BACKLOG，除非使用者明示變更優先序。
- 不要求使用者反覆貼圖、重述或手動比對；有原檔就以原檔為準。

## 2. 每階段唯一流程
讀 README／知識／架構／最近交接 → 回報現況與差異 → 選一個可驗證小任務 → 執行 → 測試 → 更新文件 → commit/push（限有權限與可用工具）→ 留下一步。
每次回報不超過四點：已做、驗證、阻塞、下一步。避免無限發散、循環辯論與一次新增多種假設。

## 3. 決策與證據
每項規則記錄 ID、狀態、來源、替代方案、衝突、測試案例、版本與決策日期。
區分「傳統定義」、「使用者提出的假設」、「Claude 雛型設定」、「已驗證軟體行為」、「獨立實證」；絕不互相替代。
未確認的選擇登錄 OPEN_QUESTIONS；不自行假裝已核准。遇矛盾先停在最小可重現範例。

## 5. 結束條件
每次工作須能回答：保存在哪裡？哪些已驗證？尚缺什麼？下次第一步是什麼？
沒有新的證據、執行結果或明確決策，就結束本輪而非重複討論。
